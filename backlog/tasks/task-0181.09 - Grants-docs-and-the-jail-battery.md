## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Starts from the integration branch after TASK-0181.08 is merged.

### Order of work

1. docs/bh-02/using/jail.md, "Grants": replace "For now nothing asks the person" with how a grant is asked and answered as it is after .08. Who asks: a row's `needs` (asked before its first start), the model's `tools.grant(...)` in its Python, an extension's `grants.ask`, a sub-agent (shown by its label), a connection the proxy refused. The question and its answers: `once` (this session), `always` (this project), `no` (this session; not asked again). Where `always` is kept: `grants.toml` in `$XDG_STATE_HOME/bh-02/projects/<project>/grants/`, which no jail reads or writes. How to revoke: `/grants`, `/grants revoke ID`, `bh-02 grants`, `bh-02 grants revoke ID`. When a grant or revoke takes effect: `net` from the next connection with no restart; `read`, `write` and `env` from the next input, after a restart of the Python process that drops its variables (the extensions process restarts at once). What is never granted (the floor), and why.
2. docs/bh-02/how-it-works/jail-and-approval.md: a "Grants" section. The broker (`runner:grants`) and the prompt (`runner:grant_prompt`); the floor in `spec_for`; generations and the restart before an input; live egress (the poller asks on a refusal, `allow_egress`/`revoke_egress`); the honest grade: `network` is best-effort, never enforced, because a program that ignores the proxy settings reaches nothing but brig cannot vouch for more, and `approval` counts best-effort as confined because of the egress policy every start passes.
3. README.md and bh-02/app/README.md: one line each on grants, linking to jail.md#grants. Check that GLOSSARY's grant, need, once/always, choose and grants entries match what shipped after .08, and add none that a user doesn't meet.
4. The battery, in bh-02/plugins/runner-cordis-plugin/tests/test_runner_live_egress.py (its helpers are private to that module, so the new cases go there and its docstring names it the battery). It already has a refused destination that prompts and, on yes, is reached; a declined one stays refused; and a revoke. Add:
   - A program that ignores the proxy: with a `net` grant standing for a TCP listener on the host's loopback, a direct `socket.create_connection` to it from inside the jail fails, while the same destination through the proxy (127.0.0.1:3128 CONNECT) is reached. This shows that a grant opens only the proxy's door.
   - A granted host that works at the start: an `always` grant already in `grants.toml` (name plus address) is reached by the first connection, with nothing asked.
   - Honest grades: a real start's grades say `network: best_effort` and `egress: proxied` (never `enforced`), and `approval` counts that start as confined. An `unconfined` start grades every part unenforced.

### Risks

- A direct connect inside the jail's netns to 127.0.0.1:PORT reaches the jail's own loopback, not the host's. The assertion is that it fails (refused, or no route), not a specific errno.
- The battery runs only under linux-jail-check. Skipped on the host, it proves nothing in scripts/check.

### Proof

scripts/check; scripts/linux-jail-check and --as-root, each with the new tests named in the output as passed. A planted failure for the ignore-the-proxy case: grant the destination, connect directly, and see the test fail if the assertion is flipped.
