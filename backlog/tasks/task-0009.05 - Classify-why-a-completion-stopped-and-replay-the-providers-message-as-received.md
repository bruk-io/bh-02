## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The loop reads "no tool call" as done, which harness/ARCHITECTURE.MD shows hides truncation, silence and undecodable calls. The loop classifies each stop and acts on it; history keeps what the provider actually sent.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
agent_cordis_plugin/stops.py: pure `classify(finish, text, calls)` after harness's table (act/answered/truncated/silent/undecodable) and harness's FEEDBACK wording. LoopModel: a `_Turn` collects chunks; only `act` runs calls; non-answered turns are fed back as a user message with `feedback: <reason>`, up to LoopConfig.max_nudges (default 2) per reply; the reply ends with a `stop` event carrying the classification. A turn that didn't act keeps no tool_calls on its transcript entry (a cut-off call never ran). The completion's `message` chunk rides on the assistant entry as `provider`; ollama's `_wire` replays it as-is. Ollama: `merged` accumulates the streamed message (content, thinking, tool_calls) as received; the done line yields usage (prompt_eval_count/eval_count) and `stop` (done_reason). Documented in CONTRACTS.md which reasons each provider can produce: ollama never undecodable; the SDK stack's stop is reported, not acted on. Not verified against a live Ollama server.
<!-- SECTION:NOTES:END -->
