## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Egress grants reach running jails, and what a jail's proxy refuses becomes a question while the call runs (decision-0012 items 4 and 6). One path for both: the broker's `on_change`.

**The pin.** brig TASK-0054 gives `EgressDecision.address` (the private address a name resolved to); the runner's brig pin (`bh-02/plugins/runner-cordis-plugin/pyproject.toml`) moves from 293a8b5 to 695a12b163777aa92839fcba37cc46dbff7f9804, brig main with it.

**Live grants.** `BrigJail` keeps the jails running now (each `_Jailed` from start until it ends) and subscribes to the broker's `on_change`. On each change it reads `granted()`, takes the `net` grants, and for every running jail `allow_egress`es each one that jail lacks and `revoke_egress`es each it holds that is no longer granted (off the event loop; `JailEgressEnded` means that jail is ending: skip it). What a jail holds is tracked by the runner, from what the start granted plus its changes. A start still passes every granted destination in its `EgressPolicy`.

**Refusals as questions.** For each running jail a poller task drains `egress_decisions` (it never blocks) about every 0.2 s, until the jail ends; it ends with the jail. For each refused decision:
- `not-granted`: `broker.ask(Request(Grant(NET, host, port), Asker(Source.INPUT, owner), reason))`, the reason saying a connection the program made was refused. Not awaited by the poller (it keeps draining); the broker already shares one question per grant and remembers a no.
- `private-address`: the same, but for `Grant(NET, decision.address, port)`, the IP literal only; the name is never offered.
- `unresolved`, `address-unparseable`, `authority-unparseable`: not asked; the model is told (below).
A destination asked once in a session is not asked again for the same jail's repeats (the broker's remembered answer).

**Who asks.** `runner.start` gains `owner: str` (keyword): the row that starts the program (`python`, `extensions`), named in the question. Its callers pass their row's name; CONTRACTS.md's `runner` row says so.

**Telling the model.** `prompting.decided` for a `net` grant answered once or always says the destination is allowed now and the call may retry it. The unasked refusals reach the model through the broker: `Broker.tell(text)` queues a line, and `grant-prompt`'s aside drains it with the decided answers (no new dependency for the runner, which must not depend on `asides`: it would reload the Python process).

**The words.** `prompting.applies` for `net`: now, on every running program, and connections already open are not affected. A `net` grant on an IP literal that is not public warns that it lets the jail reach that address on the person's network. `/grants revoke` of a `net` grant says connections already open through it stay open until the program restarts (`/clear`), as brig does not cut them.

### Risks
- A poller that outlives its jail, or a task left after `/release` or a reload: it must end with the jail and be cancelled by `_Jailed.stop`; a test counts tasks after a stop.
- The runner must take no new dependency (`asides`, `output`): it would reload the Python process. Everything it tells goes through `grants`.
- A sub-agent's program runs through the parent's runner and names itself by its row: the agent's label on a refusal is TASK-0181.08's (requesters).
- Many refusals at once (a package manager trying mirrors): one question per destination, asked one at a time by the broker; the poller never awaits a question.

### Proof
Real-jail tests (`egress_hosts` mapping a name to the host's loopback): (1) a refused destination is asked, answered once by a fake prompt, and the same program's next connection is reached with no restart (one jail, one pid); (2) a revoke refuses the next connection while a tunnel opened before it still carries a request, and the revoke's words say so; (3) a name resolving to 127.0.0.1 is asked as `net 127.0.0.1:PORT` with the private warning. A unit test that an unresolved refusal is told, not asked. `scripts/check` and `scripts/linux-jail-check` (both modes) exit 0.
