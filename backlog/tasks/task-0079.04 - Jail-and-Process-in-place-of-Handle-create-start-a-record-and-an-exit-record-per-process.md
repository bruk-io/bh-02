## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Sized 2026-10-12, before any code: about size-20, not size-5. Stopped here with a proposed split (below); nothing in brig or bh-02 changed.

What the work is, by criterion:
- AC1 Jail and Process. HostRuntime can't hold an empty bwrap instance until the supervisor (step 4), but it can hold an empty HOST instance: create = make jail_dir, clear stale records, stage files, start JAIL_LIFETIME helpers, keep the tether; the first start spawns under the exit wrapper like any later one, each process its own group. So Runtime.create loses argv and io; JailRecord.first goes; the jail is alive while any process or helper is. Every start needs the tether: today one watcher in the first group does killpg(0), so each start's wrapper starts its own watcher on a dup of the tether (the runtime holds the fd in memory; a rehydrated jail can't hold it, so it has no start).
- AC2 Records. One directory per process, <jail_dir>/procs/<id>/ holding record.json (pid, pgid, start stamp, argv, io paths) and exit (written by that process's exit wrapper, siblings included: today a sibling has no wrapper and no exit record). Replaces execs/ and <jail_dir>/exit; settles decision-162's one exit record per directory. Teardown scans procs/ with the same guards (decision-172 unknown stamp, -175 total, -171 zombies, -155 recycled). HANDLE_VERSION 5 -> 6 on Jail.to_dict (processes known at serialization in the dict, the embedder's authority; later starts found on disk).
- AC3 Where records live. Checked today: bwrap and seatbelt seal jail_dir (decision-173) but for <jail_dir>/tmp and a channel grant, and bwrap refuses only an endpoint DIRECTLY in jail_dir (decision-174). Planted on this tree: strict_linux() compiles a LISTEN endpoint at <jail_dir>/execs/k.sock and binds <jail_dir>/execs read-write into the jail (the registration directory teardown signals by). So records under jail_dir do not yet meet AC3: the compile must refuse an endpoint whose directory is, or is inside, the records directory (procs/), and the scratch name must not collide. Stacks with no fs_write mechanism (empty, env_scrub, rlimits) seal nothing: the workload runs with the embedder's uid and could signal those groups itself, so a forged record gives it nothing it lacks; the ruling says so instead of refusing every empty-stack jail. Unverifiable identities stay never signalled (TASK-0078 tests kept).
- AC4 Jail.from_dict(d, runtimes={kind: runtime}); a record naming a kind not passed is refused (law 2). Decision for the carried note: the fake gets RuntimeKind.FAKE (static grades unenforced, no mechanism names it); a FakeRuntime may run a jail compiled for any kind, its records say FAKE, so from_dict dispatches them only to a fake; test that a fake record with runtimes={HOST: HostRuntime()} is refused. start absent (not raising) when Runtime.supervisor is None: Jail and a StartableJail (or a jail whose start is set only when it has one).
- AC5 Probes: probe/runner.py already starts each probe through Handle.exec -> Supervisor.start; it becomes jail.start (Battery.run(jail)).
- AC6 SPEC 3, 8, 9 rewritten first (decision-181); runner jail.py moves (BrigJail._launched, _Jailed, its tests' monkeypatches of SubprocessLauncher.launch); brig's tests: 51 files, about 880 references to Handle/launch/handle.*, plus e2e.
