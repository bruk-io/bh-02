## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TaskWeaver's practice: its compaction carries a variable list (name, type, description) into the summary. bh-02's /compact leaves the model only its own summary of what the REPL holds. Here the list is read from the Python process at compaction time, never from the model's memory, and told with the first input after /compact or in the summary itself (the plan decides which, and what is said when no Python process is running: the intent's fifth open question). A variable is described by name, type and size; no repr.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 After /compact, the model is told each public name the namespace holds, with its type and size, from the Python process
- [x] #2 With no Python process running, /compact says nothing of variables, or says the REPL is empty, and never fails for it
- [x] #3 No value's repr is told; names with a leading underscore, tools and the startup files' functions are left out
- [x] #4 The system prompt is unchanged by it
- [x] #5 The python plugin's README and CONTRACTS.md say what crosses, where

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Reconstructed at the merge into main (2026-11-10) from the implementation notes and the branch's commits: the work was done before a plan was written.

### Order of work
1. The worker's every done carries names ([[name, description]]: type, size of an exact built-in container or string, a signature, never a repr) and unlisted.
2. PythonProcess keeps the latest listing and the startup files' names; carried() words it, capped at 3,000 characters.
3. A new broker key carried (agent:carried); the python row adds to it; /compact calls each entry off the event loop and tells the lines in the summary request and the seed's first message. Subagents keep the carried row.
4. Docs: CONTRACTS, GLOSSARY, the python, agent and subagents READMEs, the app README, the python tool page.

### Risks
- Running the model's code to describe a value (a __len__, __repr__ or property): exact type checks only.
- An entry that raises must not fail /compact.

### Proof
- test_python_worker.py, test_python_tool.py, test_agent_conversation.py, test_agent_wiring.py, test_booting.py; planted: isinstance for the exact-type guard and removing the try/except each failed a test.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Design (owner-approved 2026-10-29): the worker's every done carries names ([[name, description]], namespace order; type, length for exact built-in containers/strings, signature for function/class cut at 160, module; no repr, no user __len__/__repr__/__class__/property) and unlisted (names beyond 200, non-identifiers or over 100 chars). PythonProcess keeps the latest listing as data (name -> description) and the startup-told names; carried() words it ('the python REPL holds: hits (list, 42 items), edit(path, old, new) (function), ...', 3,000 characters then ', and N more not listed'; '' with no process or no names). New broker key carried (agent:carried, row carried, Hooks of () -> str), python row acquires carried.add; agent:conversation takes carried (Kept protocol), calls it in a thread, skips entries that raise, puts the lines last in the summary request (_ASK's namespace sentence says the list is below only when there are lines) and in the seed's first message in the past tense; nothing carried leaves both as before. Subagents: carried added to AgentsConfig.rows default so a child's python row finds it. Docs: CONTRACTS, GLOSSARY, python/agent/subagents READMEs, app README. Evidence: tests in test_python_worker.py (listing, underscore/tools, no hooks run, cap 200, signature cut/unreadable), test_python_tool.py (carried wording, empty cases, startup-told left out, N more, cleaned; python row adds to carried), test_agent_conversation.py (request, seed, raising entry, nothing carried), test_agent_wiring.py, test_booting.py.
