## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TaskWeaver's practice: its compaction carries a variable list (name, type, description) into the summary. bh-02's /compact leaves the model only its own summary of what the REPL holds. Here the list is read from the Python process at compaction time, never from the model's memory, and told with the first input after /compact or in the summary itself (the plan decides which, and what is said when no Python process is running: the intent's fifth open question). A variable is described by name, type and size; no repr.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 After /compact, the model is told each public name the namespace holds, with its type and size, from the Python process
- [x] #2 With no Python process running, /compact says nothing of variables, or says the REPL is empty, and never fails for it
- [x] #3 No value's repr is told; names with a leading underscore, tools and the startup files' functions are left out

PythonProcess keeps the latest listing as data (name -> description) and the startup-told names; carried() words it ('the python REPL holds: hits (list, 42 items), edit(path, old, new) (function), ...', 3,000 characters then ', and N more not listed'; '' with no process or no names). New broker key carried (agent:carried, row carried, Hooks of () -> str), python row acquires carried.add; agent:conversation takes carried (Kept protocol), calls it in a thread, skips entries that raise, puts the lines last in the summary request (_ASK's namespace sentence says the list is below only when there are lines) and in the seed's first message in the past tense; nothing carried leaves both as before. Subagents: carried added to AgentsConfig.rows default so a child's python row finds it. Docs: CONTRACTS, GLOSSARY, python/agent/subagents READMEs, app README.
