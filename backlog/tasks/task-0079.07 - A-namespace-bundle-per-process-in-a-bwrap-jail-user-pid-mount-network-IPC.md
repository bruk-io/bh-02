## Worker report (Claude Sonnet 5.5, 2026-10-17)

### What it does, and what it does not (read this first)
Each process a bwrap jail's supervisor starts is now PID 1 of user, pid, mount, network and IPC namespaces of its own, with a fresh /proc, a directory of its own over the jail's channel directory and scratch directory (`<jail_dir>/tmp`), no capability, and the loopback up. A `stop` ends its pid namespace, a setsid() child included. It holds where an unprivileged process can make them. **It does not hold when the jail is run as uid 0** (this machine's root, any root container): that is the graded fallback of criterion 3, reported below with the split it needs. Everything else (blocked nested user namespaces) falls back the same way.

Two measured facts shaped it (SPEC.md decision-194, decision-195, TASK-0079.07 section "Measured here"):
1. A nested user namespace can write no uid_map in a uid-0 jail with --cap-drop ALL (the kernel wants CAP_SETFCAP in the parent to map its uid 0). Unmapped works for pid/mount/net/IPC; for any other user the process's own ids map to themselves.
2. A fresh /proc in a nested mount namespace is refused (EPERM, mount_too_revealing) whenever the jail's own /proc has a mount over any of its directories, and a non-recursive bind of /proc is refused too (EINVAL, has_locked_children). decision-177's `--ro-bind /proc/sys /proc/sys` is such a cover for every user, so the bundle's /proc could not mount even for tester; and as root bwrap itself covers /proc/irq and /proc/bus with no flag to refuse it. So the cover is now emitted only for uid 0 or an unknown user (it guards kuid 0's DAC on sysctls, nothing for anyone else): `CompileCtx.euid`, `run.build_compile_ctx` sets it. As root nothing changed.

### Behaviour changes a reader will meet
A PID 1 is not ended by a signal it sends itself, and the kernel drops a signal from outside it has no handler for: the supervisor and the host's ladder read SigCgt/SigIgn and send SIGKILL for a signal that would have ended an ordinary process (so `stop` of `sleep` is 13 ms, not 2 s), and the status is -9 where it would have been -15/-2 (CPython's own interrupt exits 130). The supervisor's copy of that rule is text; a unit test holds it to teardown.term_rung. Existing tests that assumed one shared namespace or a visible supervisor now plant the block (`namespaces=False`) or read from the host; this is noted at each.

### Split proposed (not filed, per the brief)
Root: the bundle for a uid-0 jail needs the supervisor to hold CAP_SYS_ADMIN at its start long enough to unmount bwrap's /proc covers (and re-cover per process), then drop every capability: capabilities in the jail's PID 1, a design ruling. Without it a root embedder (a container) is graded cooperative, saying why.
