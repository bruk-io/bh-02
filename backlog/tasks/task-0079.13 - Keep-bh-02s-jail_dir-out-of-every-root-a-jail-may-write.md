## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-0078 (checked in a real bwrap jail): bh-02 makes jail_dir with tempfile.mkdtemp(prefix='bh-j-', dir='/tmp') (runner_cordis_plugin/jail.py, _launched). With the project anywhere else the jail can write only <jail_dir>/tmp there (Read-only file system for <jail_dir>/execs, <jail_dir>/exit). But run bh-02 with cwd /tmp (or /, or a memory root above /tmp; /private/tmp on darwin, whose Seatbelt profile allows file-write* under the project subpath) and the project write root covers /tmp/bh-j-*: the jail then wrote <jail_dir>/execs/1.json, <jail_dir>/exit and <jail_dir>/x, all seen on the host, and a malformed execs/1.json made the jail's stop() raise JSONDecodeError out of brig's kill (teardown.py _live_exec_siblings -> _execs.live). A forged exit file forges the exit status; a forged registration with a stamp still reaches a group (decision-172's stated residual).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Design as accepted, made generic: brig has no notion of 'tmp/', so the law is: a write root AT or ABOVE the jail_dir grants nothing in it; a write root strictly INSIDE the jail_dir (bh-02's <jail_dir>/tmp scratch) keeps its grant, and so does a declared LISTEN channel's own grant (bwrap's endpoint directory, seatbelt's socket literal), which the fs_write detail already names. bh-02 needs no change.
1. SPEC.md first: decision-173 in §5 (the law) plus the §6 bwrap stage list and seatbelt order; a pointer from decision-172's residual.
2. Tests first, seen failing: unit (bwrap render: a write root above jail_dir -> --ro-bind of jail_dir after the write roots, inner roots and channel dirs re-bound after it, pins/carve-outs inside the sealed part not mounted; no seal when no root reaches jail_dir, so goldens stay; seatbelt render: deny subpath jail_dir after the allows, inner roots re-allowed, before write_denies); integration (real bwrap jail, write root = an ancestor of jail_dir under my own scratch dir: execs/1.json, exit, x refused with EROFS, <jail_dir>/tmp write lands - control in the same test).
3. Implement: render_bwrap_prefix gains required jail_dir (Bwrap.compile passes ctx.jail_dir); pure helpers decide the seal; seatbelt render_sbpl emits the deny + re-allows.
4. Grades: unchanged (seal narrows writes; never grade up); fs_write detail names the seal.
Risks: bwrap --ro-bind is recursive-remount and hides in-namespace submounts under jail_dir, so everything writable inside it must be re-bound after; a pin or an absent carve-out under the sealed part would re-grant or fail the launch (tmpfs mount point on a RO mount), so both are skipped there. Seatbelt precedence (later wins, both directions) is the parent's probed fact; no darwin run here (TASK-0079.15).
Proof: unit + integration tests seen red before the fix; uv run pytest libs/brig; scripts/arch-check; scripts/check; tester+tini runner plugin tests; scripts/linux-jail-check with proxy env.
