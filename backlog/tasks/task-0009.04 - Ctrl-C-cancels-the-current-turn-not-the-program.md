## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A long reply or tool run can only be stopped by killing bhh. Interrupt stops the turn and the session carries on.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Ctrl-C during a reply stops it, says so, and returns to the prompt
- [x] #2 A tool call cut off by an interrupt leaves the transcript valid for the next request
- [x] #3 Ctrl-C at an idle prompt does not end the session; Ctrl-D and /exit still do
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
`input.interrupted()` added to CONTRACTS.md and chat's Input. `converse` runs each turn through `_interruptible`: races the reply against `interrupted()`, cancels the turn (the reply generator closes, so the SDK provider's interrupt-and-drain runs), and shows a `stop: interrupted` event. Terminal: `Interrupts` (entered by the console row) takes SIGINT on the first interactive read, so `bhh ask` keeps Python's Ctrl-C; at an idle prompt Ctrl-C prints how to leave; on exit it restores the previous handler (asyncio.run installs its own, which remove_signal_handler would lose). LoopModel answers every call left unanswered by an interrupt with an "interrupted" tool message (try/finally), so the transcript stays valid.

Found and fixed: the SDK starts Claude Code's CLI in bhh's process group, and the CLI exits on SIGINT (probed: returncode 0 after killpg). New console script `bhh-claude-detached` (claude_agent_sdk_cordis_plugin/detach.py) setsid's and execs the real CLI (bundled binary, else PATH), set as `cli_path` via `detached_cli()`; probe after: CLI stays up. terminal-io rule now exempts `sys.argv`/`sys.executable` imported by name (not terminal I/O).

Verified live in a pty with --model haiku: counting reply interrupted at 13, "stopped: interrupted", then the same session answered the next message.
<!-- SECTION:NOTES:END -->
