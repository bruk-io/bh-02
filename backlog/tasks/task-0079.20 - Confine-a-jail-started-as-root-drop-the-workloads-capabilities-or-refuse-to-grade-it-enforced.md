## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-0079.01 and its review (2026-10-12). Run as root, strict_linux()'s workload is host root inside: uid_map '0 0 1', CapEff and CapBnd full, CAP_SYS_ADMIN over its own mount namespace. Its read-only binds are not locked: inside the jail 'mount -o remount,bind,rw /etc' succeeded and 'touch /etc/<probe>' created a root-owned file on the HOST's /etc (the reviewer removed it). CAP_DAC_OVERRIDE also reaches host files owned by the mapped uid 0 (a root-owned mode-000 file was readable). So fs_write grades ENFORCED and is void as root: any path the jail can see can be made writable. bh-02 run as root (a container, CI) is affected. As an unprivileged user none of this applies (bwrap leaves no capabilities).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Findings (measured as root, bwrap 0.9, scratch dir only): by default bwrap run as root unshares a user ns mapping '0 0 1' and keeps CapEff/CapBnd full (NoNewPrivs 1); a remount,bind,rw of a read-only bind of <scratch>/ro succeeded and touch wrote <scratch>/ro/planted on the host; a root-owned mode-000 file read. --cap-drop ALL: CapPrm/CapEff/CapBnd empty, NoNewPrivs 1, remount EPERM, touch EROFS, mode-000 EACCES; a nested unshare --user --mount cannot unlock the binds (no map for uid 0 without CAP_SETFCAP; copied mounts locked). Second hole the caps don't close: the workload is still kuid 0, and sysctl permission is DAC only (owner bits for global root), and bwrap 0.9 skips covering /proc/sys (its access(W_OK) on the r-xr-xr-x dir fails), so capless root wrote /proc/sys/kernel/hostname (shown safely in the jail's own UTS ns); core_pattern/modprobe are the same check -> host root code. --remount-ro /proc/sys fails (not a mount point); --ro-bind /proc/sys /proc/sys works as root and tester (EROFS). An unprivileged --uid/--gid inside is not needed and would not help: bwrap maps it to host uid 0 anyway (sysctl DAC unchanged), and it changes the uid the workload sees. Choice: emit --cap-drop ALL (stage 1) and --ro-bind /proc/sys /proc/sys (stage 2) unconditionally: compile stays pure (no uid in ctx), and both are no-ops for an unprivileged user (no caps; mapped uid not global root). Nothing brig runs inside the jail before the workload needs a capability (env_scrub's sh/env; the rlimits trampoline, exit wrapper and tether are outside bwrap; exec siblings use the same prefix). Order: 1) SPEC.md §6 ruling decision-177 (+ seatbelt: MAC, uid-independent; Mac check carried to TASK-0079.15). 2) root-only integration test (CapEff/CapBnd, remount, scratch write, mode-000 read, /proc/sys hostname write) run red before the fix. 3) bwrap.py stages 1-2, docstrings, unit goldens. 4) proofs: root suite, tester+tini tiers, linux-jail-check, bh-02 runner tests as root, scripts/check. Risks: a workload/test that relied on root caps (none expected); host without /proc/sys fails the launch closed. Follow-up: /dev is a writable tmpfs in every jail (jail-local, not root-specific) -> new task.
