## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-0079.01 and its review (2026-10-12). Run as root, strict_linux()'s workload is host root inside: uid_map '0 0 1', CapEff and CapBnd full, CAP_SYS_ADMIN over its own mount namespace. Its read-only binds are not locked: inside the jail 'mount -o remount,bind,rw /etc' succeeded and 'touch /etc/<probe>' created a root-owned file on the HOST's /etc (the reviewer removed it). CAP_DAC_OVERRIDE also reaches host files owned by the mapped uid 0 (a root-owned mode-000 file was readable). So fs_write grades ENFORCED and is void as root: any path the jail can see can be made writable. bh-02 run as root (a container, CI) is affected. As an unprivileged user none of this applies (bwrap leaves no capabilities).
<!-- SECTION:DESCRIPTION:END -->
