## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The baseline for TASK-0173: scripts/model-friction reports, per session, the inputs that redo work an earlier input of the same REPL already kept in a variable. What counts as a miss is decided here (the intent's first open question): candidates are the same program or search run again, a name assigned again from the same expression, and a file read again with no write to it in between. Where the evidence allows, say which cause a miss looks like (a name forgotten, state not trusted, a variable's content unknown). A REPL restart starts a new REPL: work redone after one is not a miss.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
reuse_miss: a top-level assignment of an input that ran without an error keeps an expression that works (reads files, runs a program, calls a tool); a later top-level statement holding the same expression (ast.unparse) is a miss, unless something between could change it: a statement that writes, runs a program that is not read-only or calls a tool, another tool's call, binding again the holding name or a name the expression reads, a new REPL (the opening's 'started again', or a run start in rows.jsonl between the two calls' at). So it is a floor. Each miss says how: kept again in the same name, kept under another (a name forgotten), or computed again without keeping. Criterion 4 waits on the owner: run scripts/model-friction on the machine with sessions and record the reuse_miss line in TASK-0173's notes.
