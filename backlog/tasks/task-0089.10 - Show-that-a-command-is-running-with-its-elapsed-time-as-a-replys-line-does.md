## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while building TASK-0089.06. The working line (Working · 12s) follows the ui's TurnStarted/TurnEnded, which the output posts around output.show. A reply is shown as it streams, so it is covered; a command (a ! one, up to its 120 s timeout, /compact, /model) is shown only once it answers (chat.converse runs commands.run, then output.show(answer)), so while it runs the screen still shows nothing moving and the only word is Ctrl-C's 'a command is running'. The signal for 'a line is being handled' exists in the bridge (_busy: a line handed out, nobody has read since) but not as a public one the app can follow, and it is true of a reply's start too. Decide in the plan where the app learns a command began and ended (the bridge already hears read() and line handed out), and whether the line says the same thing for a command.
