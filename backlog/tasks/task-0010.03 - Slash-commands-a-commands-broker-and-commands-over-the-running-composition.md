## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A coding harness has /help, /clear, /model and a way to see what is running. Commands are registered by rows into a broker (like tools); the session sends /x lines to it. Composition commands act through the loader handle, which gains restart and explain as operator API in cordis.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 /help lists every registered command; a row that leaves takes its commands with it
- [x] #2 /rows shows each row and its state; /explain ROW shows cordis's diagnosis
- [x] #3 /clear starts the conversation and the kernel afresh without ending bhh
- [x] #4 /model NAME switches the model by editing the session's layer file, and the switch survives a resume
- [x] #5 An unknown /command says so and suggests /help; it is never sent to the model
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
cordis: Loader gains `restart(rid)` (a fresh fiber; dependents reload), `explain(rid)` (Inspection's diagnosis, or disabled/unresolved/no such row), and a change lock so a watcher reload and a restart never interleave; boot's unsatisfiable check knows the loader provides `loader` (tested: a row injecting `loader` activates, nothing reported); `format_layer(rows)` in cordis.composition, parse_layer's inverse (round-trip tested). New member commands-cordis-plugin: `commands:registry` binds `Commands` (broker via cordis_helpers.Registry; /help built in; unknown → "unknown command /x; /help lists them"; a failing command → "/x failed: ..."), `commands:operator` depends on `commands` and `loader` and registers /rows, /explain ROW, /restart ROW, /clear, /model [NAME]; restarts are queued to the operator row's own background work (a restart replaces rows the session depends on, which would cancel the session's own task mid-command). /clear empties `forget` files (the Claude session id or transcript) then restarts `clear` rows that exist (llm, transcript, kernel). /model edits the session layer (`layer`, `model_row`) via cordis's read_layer/format_layer and lets the watcher reload. chat:session depends on `commands`; `is_command` (a /name then whitespace or end: `/tmp/x.py` is not a command) routes lines to it and shows the answer as a `note` event (drawn cyan on stderr). bhh.toml gains `commands` and `operator` rows; the session layer configures the operator. Tests: plugin (8), chat routing, a composed session (/rows, /clear then a message, /model, /nope). Live (haiku→sonnet): /model kept the conversation ("zebra"), /clear dropped it ("unknown"), /rows showed 14 rows active.
