## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The runner's policy (`spec_for`) takes two lists from the old brig, `SELF_MODIFY_WORKSPACE_RELATIVE` and `CREDENTIAL_READ_DENIES_HOME_RELATIVE` (`brig.core.threats`). They are bh-02's knowledge (which files can run code outside the jail later, which hold a person's credentials), and the new brig has no such lists and should not (it knows nothing of its embedders). Moving them into the runner plugin is needed for the swap and changes no behaviour, so it lands now, against the old brig (decision-0011).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->

- [x] #2 The runner's error for an unknown `allow` name, and its docs, name the plugin's list, not brig's
- [x] #3 No behaviour changes: the runner plugin's tests pass unchanged but for where the names come from, and scripts/check passes
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
### Order of work
1. `jail.py`: define the two lists as module constants beside `BASELINE_ENV` and `SYSTEM_READABLE` (`#:` comment each, the old brig's entries in its order, at c0a7d48), private unless a caller outside the module needs them; drop them from the `brig.core` import.
2. Reword what names brig's lists: the module docstring, `BrigConfig`, `spec_for`, `self_modify_denied` and its error, the runner README, and the two test comments that call them brig's.
3. scripts/check for the runner plugin, then the whole of scripts/check.

### Risks

### Proof
A test asserts the plugin's lists equal brig.core.threats' (removed with the old brig in TASK-0176.08); the runner plugin's existing tests pass unchanged; scripts/check passes.
