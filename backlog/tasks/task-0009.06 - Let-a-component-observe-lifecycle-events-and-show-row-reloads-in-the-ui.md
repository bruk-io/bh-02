## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Reshaping the running program (a layer edit, the model's write_file) is invisible without --trace. A component can't reach the runtime, so observing lifecycle events is a new cordis effect, and the terminal shows reloads and failures.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
cordis: `observe(fn)` (seventh effect, exported with `Event`): appends a wrapped listener to rt.listeners; undo removes it. A listener that raises is taken off, its error kept on its fiber, and an `observe-failed` event emitted; `emit` iterates a copy of listeners so one can leave mid-emit. Tests in test_effects.py; test_invariants passes; README says seven. terminal: console yields `observe(output.lifecycle)`; `render.lifecycle_line` is silent the first time a row goes active (boot) and shows `↻ row reloaded` after, and `✗ row failed: error` for failed/work-failed/observe-failed/teardown-error. Verified live in a pty: toggling `approve` in a watched --patch file printed `↻ approve reloaded`; a bad `llm` config printed `✗ llm failed: TypeError(... Did you mean 'model'?)`. Not covered: a row that becomes unresolvable (bad `use`) has no fiber and so no event; it is reported by the bootstrap at exit ("stopped early") as before.
<!-- SECTION:NOTES:END -->
