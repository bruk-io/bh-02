## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Plan (2026-10-12). Order of work, Spec first, every step green.

1. SPEC.md first, decision-184 (highest today is 183): §10.1 and §5's channel bullets, §6 (bwrap, seatbelt), §8 (Supervisor.start takes `channel`), §9 (Process fields, wait_ready).
2. Where the channel directory lives: `<jail_dir>/chan`, chosen by the runtime (never the Spec), passed to compile as `CompileCtx.channel_dir`. Squares with the rulings: decision-173's seal still covers the rest of jail_dir, and `chan/` replaces "a declared LISTEN channel's own grant" as the one writable thing in it beside `tmp/`; decision-174 holds by construction (the grant is a subdirectory, never jail_dir itself); decision-181 holds by construction (`chan` is not `procs`; it is a name brig keeps in jail_dir beside `tmp`, `procs` and `jail.json`, and a process's own files stay under `procs/<id>/`). The three channel refusals (ChannelInsideJailDir, ChannelOnRecords, ChannelInsideWriteDeny) stop being reachable from a Spec: they become a check that the ctx's channel_dir is jail_dir/chan, and a write_deny at or above jail_dir/chan is refused at compile.
3. The Spec names channels: `Channel(name, kind)`, no `endpoint`; `SPEC_VERSION` 1 -> 2; `narrowed_to`'s endpoint-conflict refusal goes (a name either is declared or not); `_dicts` and the jail dict's `channels` follow, `JAIL_VERSION` 6 -> 7.
4. bwrap compiles one `--bind <chan> <chan>` at create, stage 4 (where the per-endpoint directory binds are now); `_mounted_roots`, `channel_dirs` and the pins use it. seatbelt: `(allow file-write* (subpath CHAN))` in place of each endpoint literal, still after the seal; network-bind unchanged. seatbelt's half is profile-unit-tested only (no darwin here) and says so.
5. Each start: `Supervisor.start(argv, *, cwd, io, channel: str | None)`; naming a channel the Spec does not declare raises (`UnknownChannel`). HostRuntime makes `<chan>/<process id>.sock` as the bound path; `ProcessRecord` (record.json) and `Process` carry `channel`, `bound_path` (in-jail) and `endpoint` (host path to dial); for HOST both are the same path. The fake runtime mirrors it.
6. Readiness moves into the runtime: `Runtime.endpoint(jail, process) -> str | None` and `Process.wait_ready(timeout)` (connect, never path existence); `Jail.wait_ready(channel)` goes.
7. The network battery's bind probe binds a fresh name inside the channel directory instead of the declared endpoint.
8. bh-02: `Runner.start(argv, cwd) -> started`, `started.endpoint`; runner_cordis_plugin/jail.py declares `Channel("kernel")` and starts with `channel="kernel"`; unconfined.py makes its own socket path; python_cordis_plugin.client and extensions_cordis_plugin.host dial `started.endpoint`; their fakes (extensions testing.py) and five test files follow.

Open design question (needs the owner): how the started process learns its bound path. argv is fixed before the start, and env_scrub's wrap is `env -i` with names fixed at create, so a per-start variable is dropped. Options: (a) brig sets `BRIG_CHANNEL` per start and every env mechanism forwards that one name as brig's own (a ruling on env_scrub); (b) a two-phase start: `jail.channel(name)` reserves a path the embedder puts in argv, then `start(argv, channel=reservation)`; (c) a fixed in-jail path per process, which needs a mount namespace per process (TASK-0079.07), so not before it.

Risks: Spec dict and jail dict versions bump; about 24 brig test files (263 lines) name an endpoint; bh-02's runner contract changes in three plugins and the app.

Proof: a test that an undeclared `channel=` is refused (seen failing first); bwrap golden argv with exactly one channel bind; a bwrap integration test that two starts get two sockets in one jail, each dialled from the host; brig tiers (root and tester under tini), runner/python/extensions/app tests, arch-check, mypy, linux-jail-check, scripts/check.

Sizing: this is well over size-3 (a Spec API and two dict versions, both mechanisms, the runtime protocol, the battery, ~24 brig test files, and bh-02's runner contract across three plugins). Stopping after the plan, per the brief, with a proposed split in the notes.
