## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Order: (1) sessions.py: ROWS = rows.jsonl and Session.row_log. (2) bootstrap.py: pure _row_line(event, at) keeping the kinds cordis emits for the events that count (reload, failed; cordis emits no restart kind: a restart is the old fiber's unloading/inactive then the new fiber's reload, so it is kept as that reload) and an async context manager _row_log(runtime, path) that appends a listener which only queues the line to host_paths.Appender (never writes on the loop; a write error removes the listener, the run goes on) and closes the Appender after shutdown; run(..., rows=PATH). cli passes session.row_log; --trace writer untouched. (3) viewing.py reads rows.jsonl through read_beneath (no link, cap) and hands the bytes to trajectory(). (5) Tests: writer (0600 under umask 0, kinds, restart/failed/sub-agent row, off-loop write spy, write failure does not stop run, --trace unchanged), trajectory ordering test, viewing/follow test, link refused. Plant: write synchronously on the loop and drop the OSError handling, see the tests fail. (6) Docs: GLOSSARY session + trajectory, app README, docs sessions + command-line, host-paths/CLAUDE notes; purity budget entries in root pyproject if the gate flags them. Done (AC #4 half: GLOSSARY names rows.jsonl in the session entry, plus new rows.jsonl/row log, lifecycle event and bh-02 trajectory entries; 'scripts/check passes' left unticked, the reviewer's to prove).

What changed: sessions.ROWS and Session.row_log; bootstrap._row_log (async context manager) + run(row_log=PATH): a Runtime listener beside --trace's, built on cordis's public Event (kind, fiber, error), that only queues a line to host_paths.Appender (opened and written on its thread, 0600, no link); a failed write removes the listener and the run goes on; the Appender is closed after shutdown so the unwinding is written. cli passes session.row_log; --trace's writer is untouched. viewing reads rows.jsonl through read_beneath (no link, cap) and hands the bytes to trajectory(); trajectory.rendered places each reload before the first later-timed line of the owner of its row (the session's own spine, or the sub-agent's block for agents/NAME/...), at that line's depth, the rest last; Line gained at/depth. Root pyproject purity budget: _row_log, _row_log.hear, run.

Finding: cordis emits no restart kind (kinds: reload, active, unloading, inactive, failed, failed-inactive, teardown-error, cancelled, bind, unbind, work-failed, observe-failed). Loader.restart ends the old fiber unloading+inactive and the new fiber begins with reload, so a restart (and a row's first load, and a dependency-driven reload) is kept as that reload; the kept kinds are reload and failed. decision-0009 names restart; if the owner wants it labelled apart, the shell would have to derive it (a name seen before with a new uid). Boot writes a reload per row (about 34 lines a boot, 15 more per sub-agent), shown as they are.

Evidence: tests/test_row_log.py (7: file mode 0600 under umask 0 and only reload/failed in time order, same rows as --trace; /clear restart; failed row with its error though the run stops; agents/ row kept; open+write spy proves nothing touches the file on the loop thread; unwritable log ends and the run goes on; no file unless asked), test_command_line (session dir rows.jsonl 0600 and its rows equal what --trace traced), test_real_launch agents test (real sub-agent rows agents/general-1/loop and /python in rows.jsonl), test_trajectory (ordering across steps, calls, nested calls, sub-agent block, replies, trailing; ties; per-owner; dates; control characters; stable keys), test_trajectory_view (read, absent, link/hard link/over cap refused, --follow prints a new reload once).
