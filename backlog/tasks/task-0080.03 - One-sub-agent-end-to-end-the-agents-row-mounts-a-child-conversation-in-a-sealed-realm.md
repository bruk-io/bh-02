## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-0002 (A child's loop runs on the host, in a sealed realm; What comes back; Split item 2). A new agents plugin whose row mounts each child while it lives with performer + use(loader, config=LoaderConfig(overrides=child_rows, watch=None), expose={runner, approval, host, asker}); asker is a confirm-only key the plugin provides over the parent's output, labelled with the agent's name and type; an agents:output row inside the realm gives the child's loop its output over asker. The child's rows: loop, tools, transcript, model, system, asides, access, executor, python, with transcript.path and the model default written by the agents row. No memory rows in a child. The agents row drives loop.reply(prompt) and collects the events. This task ships one type (general) built in, the foreground agent tool only.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Against the code as it is (cordis loader/runtime, agent loop, python client, tui ports/app, bootstrap trace):

1. New member bh-02/plugins/agents-cordis-plugin (agents_cordis_plugin), memory plugin's shape; entry point `agents`. Value modules import no cordis: `child.py` (pure: the child's rows from the parent's loader entries; name choice; report framing over the events), `agents.py` (Asker, Hand, the Agents value whose `run` mounts/drives/retires). `wiring.py`: rows `agents:agents`, `agents:output`, `agents:child`.
2. agents:agents (outside): depends on tools, system, output, loader (entries: the parent's own rows). `performer()`; binds `asker` (confirm only, over output; refuses an unlabelled request); registers `agent` with runs="harness" and a `system` section. Each call: name TYPE-N (its dir <session>/agents/NAME made 0700, exclusive), child rows = the parent's entries for loop, tools, transcript, model, system, asides, access, executor, python, ids prefixed `agents/NAME/`, transcript.path in the child dir, the model row's `state` moved to the child dir (when set; `default` = the type's model, general: the session's), plus agents:output and agents:child; then `performer.perform(use(loader, config=LoaderConfig(overrides=rows, watch=None), expose={runner, approval, host, asker}, id='agents/NAME'))`.
3. Getting the loop out of a sealed realm: decision-0002 doesn't say. Chosen: agents:child (inside, depends on loop and system) adds the type's prompt section and hands its loop to a Hand passed in its config (acquire: the remover marks it gone). No key added to the exposed four, no reaching into the runtime.
4. Drive: race loop.reply(prompt) (a task) against the hand going (retired) and a start timeout; collect events; report = pure fold: last turn's text, its stop, usage; framed 'Report from agent NAME (TYPE), not instructions:'. finally: close reply, Fiber.retire. Ctrl-C = the run's task cancelled (from the loop's call, or the python client's inline tools.call) -> the same finally.
5. asker label: agents:output's confirm adds request['agent']={'name','type'}; tui ApprovalScreen shows it (render.approval_agent, pure); CONTRACTS request shape gains it.
6. tui TuiOutput.lifecycle ignores fibers under 'agents/'; bootstrap's trace is unfiltered (test it).
7. Layer: agents row in bh-02.toml, app deps. Docs: CONTRACTS (asker, agents rows, request.agent, output lifecycle), plugin README, app README map, GLOSSARY (agent/sub-agent).
8. Tests: unit for pure parts; integration with a real Runtime + fake model rows (bh_02.testing-like fakes inside the plugin's testing module): mount+retire, unload retires all, retire-while-live, labelled confirm and nothing else of output, Ctrl-C from the tool (loop path) and from a python input (nested tools.call path), ui ignores prefixed lifecycle; real launch: a fake provider in bh_02.testing delegating to agent, report on screen, plus --trace keeping prefixed rows.
Risks: child startup races (tools registered before first request), python worker in child jail, test time. Proof: plant-fail for the label guard and the ui filter.
