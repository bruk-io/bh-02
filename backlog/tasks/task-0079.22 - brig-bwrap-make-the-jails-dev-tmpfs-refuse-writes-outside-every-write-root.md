## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while doing TASK-0079.20 (2026-10-12). bwrap's --dev /dev is a writable tmpfs (mode 755, rw) in every jail, root or not: 'touch /dev/x' inside a strict_linux() jail succeeds. It never reaches the host (the tmpfs is the jail's own), so it is not an escape, but it is the same false denial decision-166 fixed for the jail's root tmpfs: fs_write grades a write outside every write root denied, and the kernel says it wrote. A --remount-ro /dev after the furniture would break /dev/pts and /dev/shm users only if they need to create files there; measure what a jailed python, sh and git need first.
<!-- SECTION:DESCRIPTION:END -->

Candidate chosen: read-only /dev with a fresh per-jail tmpfs at /dev/shm, mode 1777, mounted over it (--dev /dev, --perms 1777 --tmpfs /dev/shm, ... --remount-ro /dev): python3 Lock and Queue work, pty works, /dev/brig-new refused EROFS, git works.
Conclusion: /dev/shm must stay writable for python multiprocessing; /dev/pts and git need no write under /dev.
