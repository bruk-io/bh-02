## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Reframed by the orchestrator (2026-10-12): not a flaky test but a product race from TASK-0079.25. wait() answers once the exit record exists, which the wrapper writes just before it exits; for those milliseconds create over the same jail_dir correctly refuses (decision-181: refuse while anything recorded runs). An embedder reasonably expects a jail_dir to be reusable once wait() returned. TASK-0079.23's sweep fix only made the race visible here instead of in the sweep.

Cause: the exit record is written before the wrapper exits; wait() returned on it, so create saw the wrapper (stamp held, not zombie) as RUNS ('names process group N, which still runs'). Fix: _recorded_status returns None while _waiters.is_watched(pid); wait() then answers from the waiter record, set after reap. New test test_wait_returns_only_once_the_process_has_left_so_the_jail_dir_is_free (50 wait-then-launch rounds) failed 4 of 5 runs before the fix, 0 of 50 after (together with the second-launch test, root, no tini). Rehydrated wait(): decision-182 says it guarantees only the exit record; JailDirInUse now names pid and group and says wait and retry, or destroy. Results: brig as root 948 passed 24 skipped; as tester under tini 947 passed 25 skipped; runner plugin 58 passed 1 skipped; scripts/check as root rc=0 (2328 passed). Not run: scripts/linux-jail-check.

Fix round after review 1: wait() in the starting process now prefers the exit record once the waiter has reaped (pure _chosen_status, unit-tested for present/absent and agreeing/disagreeing); decision-182 amended with which wins and why; wait() docstring says the leader has left (children in the group still hold the dir); unit test pins JailDirInUse's 'pid N' and 'process group M'. brig as root 953 passed 24 skipped; arch-check --no-fix 0; mypy clean; ruff clean.
