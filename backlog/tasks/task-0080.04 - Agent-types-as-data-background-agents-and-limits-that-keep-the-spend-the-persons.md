## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Order of work (all in the agents plugin but #5, which is the tui's):
1. child.py (pure): AgentType gains steps (30) and tools (the row ids it grants); shipped general and explore (python, the session's model). parse_type(name, text, source) -> AgentType, a ValueError naming the file, the field and what to write: not TOML, an unknown field, a wrong type, steps < 1, a tool naming agents (depth one), extensions or MCP (never grantable), a tool not among the agents row's grantable rows (new config `tools`, default ["python"]). child_rows keeps the conversation rows of `rows` and, of the tool rows, only those the type grants. steps_ended (a fold over a reply's events); the budget and model questions as pure functions; Report keeps cached tokens; the usage event a child's end shows.
2. Types are read per call: each host.trusted directory's agents/NAME.toml (the first there), refused unread when reading it passes through the working directory (host_paths.passes, as the models file); a person's type of a shipped name replaces it.
3. agents.py: agent(prompt, type, model?, background?) and agent_wait(names, timeout); max_running (4): a call waits for a slot and a note says so through the parent's output.show; session_agents (16): past it each call is asked (output.confirm, a labelled request), a no refuses with text saying so; a model other than the type's (the type's, else the parent's model row default) is asked the same way; the step limit closes the child's reply at a step boundary and its report says the limit ended it; each child's usage shown (a usage event, after a note naming it) through output.show when it ends, however it ends. Background runs kept by the row and cancelled with it.
4. wiring: the agents row also depends on host (types from host.trusted); not on models: the session's model name is the parent's model row config, and a model name that can't be used fails the child's first step, which its report says. Registers agent and agent_wait (runs="harness").
5. tui: Ctrl-C declines only the questions not labelled with an agent; the foreground child's is withdrawn by its cancellation (as today), a background child's stays queued.
6. Docs: CONTRACTS, the plugin README, the app README map, GLOSSARY. The real-launch assertion of the python tool's note gains tools.agent_wait.
Risks: the usage shown mid-turn is a turn of its own in the ui (a block break); the session budget counts this row's children (a restart of the row starts it again), said in the README. Size: one new dependency (host), no cordis change: within size-3, at its edge.
Proof: unit tests of parsing, every refusal and the decisions; wiring tests over the scripted model for background and agent_wait, max_running, the step limit, budget asked yes and no, model asked, usage shown; a tui Pilot test that Ctrl-C leaves a background child's question queued; each guard planted failing first.
