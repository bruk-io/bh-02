## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The approver reads stdin while a reply is streaming, so its prompt lands mid-line. Approval becomes a question the output answers.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The approver asks the `output` value, and the terminal asks on a fresh line
- [x] #2 A denied call reaches the model as a denial, not a failure
- [x] #3 Retiring the ui row takes the approver's guard with it
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
`output` gains `confirm(request) -> bool` (CONTRACTS.md; `request` = {name, input}). `terminal_cordis_plugin.approval.ask_first(output)` is the guard: it knows no terminal. `terminal:approver` depends on `tools` and `output`; TerminalApprover (a stdin read inside a guard) is gone. `TerminalOutput.confirm` ends any streaming line first, then reads through the shared StdinReader; prompt is uncoloured because readline counts escape codes as width. A code cell is asked about as a cell. Tests: fresh line + only-yes, the cell wording, the guard's denial reason, and retiring the ui row withdrawing the guard (a Runtime test).
<!-- SECTION:NOTES:END -->
