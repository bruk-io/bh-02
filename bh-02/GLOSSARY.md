# Glossary

The words you meet using or changing bh-02, one line each. bh-02 is built on cordis and keeps
cordis's words as cordis defines them; the rest are bh-02's own. [`CONTRACTS.md`](CONTRACTS.md)
has the exact shapes, [`app/README.md`](app/README.md) the rows as shipped, and the page a line
links to the detail.

## cordis's words

As [cordis's README](../libs/cordis/README.md) defines them (its "Concepts").

- **plugin**: a package that ships components, found through its `cordis.plugins` entry point (`tui`, `agent`, `python`, `runner`, ...).
- **component**: a recipe for one part of the program: what it needs, and the effects it yields; a layer names one as `plugin:component` (`agent:loop`).
- **row**: one entry of a composition: `id` (its role), `use` (which component fills it), `config`, `disabled`.
- **layer**: a TOML file of rows, as `[[plugin]]` tables, applied in order over the layers before it ([Layers](../docs/bh-02/using/layers.md)).
- **loader**: the part of cordis that reads the layers, starts the rows, and swaps only what changed when a layer file is edited; its handle is bound as `loader`.
- **key**: the name a value is bound under, and the name of the parameter a component reads it by; two plugins agree on a key by name, never by importing each other.
- **binding** (`bind`): a value held under a key, for as long as the row that bound it is up.
- **dependency**: a key a component needs: it runs only while every one is bound, and reloads when one is replaced.
- **provider**, **consumer**: the row that binds a key, and a row that depends on it (not a **model provider**, below).
- **contract**: the shape a component asks of a dependency: a Protocol of its own, checked when the value arrives.
- **effect**: one step a component yields, with its undo: `bind`, `acquire`, `enter`, `use`, `background`, `performer`, `observe`.
- **undo**: the other half of an effect, which reverses its step (unbinds the key, calls the remover, exits the context); a row's undos run in reverse order when it goes.
- **provides=**: the keys a component declares it binds (`@component(provides=(...))`), checked, not inferred.
- **unresolved** (row): a row whose `use` names no plugin or component bh-02 has, or whose module failed to import; cordis reports it and runs the rest, but at launch bh-02 stops with its error ([Layers](../docs/bh-02/using/layers.md#a-layer-that-names-what-bh-02-doesnt-have)).
- **acquire**: an effect that calls a registration and keeps the **remover** it returns (the function that takes the entry back out), called when the row goes.
- **broker**: one row binds a registry; others register into it with `acquire`, and leave without reloading anyone (`commands`, `frame`, `tools`).
- **fiber**: a component running as a row, with a state: loading, active, unloading, inactive, failed.
- **lifecycle event**: what a fiber just did (`reload`, `bind`, `active`, `unloading`, `inactive`, `failed`); `observe` hears them, `--trace` writes them, and a session keeps its `reload` and `failed` events in `rows.jsonl`.
- **reload** and **restart**: a row started again because its layer changed or a dependency was replaced (reload), or because an operator asked (`restart`, as `/clear` does).

## bh-02's words

- **bh-02**: the coding harness: a terminal app where a model works by writing Python.
- **harness**: a program around a model that runs its loop and its tools and decides what it may do; bh-02 is one, built on cordis.
- **harness** (the project): a separate project of the repository's owner whose `ARCHITECTURE.MD` gave bh-02 CodeAct and its step table: "harness's rule", never read a truncated or silent step as the answer (`stops.classify`).
- **DeepSeek Harness**: the agent harness built on the paper cordis realises (cordis's README); its account of tool registries, tool changes and model-written plugins informed bh-02's designs.
- **the harness's** (a line): bh-02's rather than the model's: a slash command, or a line with a prefix a row claimed, as `commands` decides (`claims`).
- **harness** (in brig's docs and tests): the program that starts the jails, such as bh-02; in brig's tests, the test run itself (`harness_pid`).
- **the shell**: `bh_02` (`app/`): the `bh-02` command, which reads the layers, boots them and waits for the chat to end.
- **layer files**: `bh-02.toml` (the whole harness), a session's `session.toml`, and your `--patch` files, applied in that order.
- **stack** (a session's): the model a session started on, kept in its `meta.json` and listed by `bh-02 sessions`; not always the model that answered.
- **stack** (brig's): the mechanisms brig composes into one jail; bh-02's runner uses `scratch_darwin()` (Seatbelt) on macOS and `strict_linux()` (bubblewrap) on Linux (`stack_for`).
- **stack** (a fiber's, in cordis): the undos a fiber has recorded, run last first when it unloads.
- **loop** (row and key): the agent loop, `agent:loop`: sends the conversation to the model, runs each call it asks for through its tool, and nudges a step that didn't count ([The loop](../docs/bh-02/how-it-works/loop.md)).
- **model** (row and key), **the model row**: the model itself, one step at a time (`models:model`), the one its `default` names, chosen by `--model NAME` or `/model NAME`.
- **named model**: a name the model row can take, with its provider and id: an endpoint's model in the models file (`ENDPOINT/MODEL`); bh-02 has none built in.
- **endpoint** (a table of the models file): a server and how to reach it, with its models under its `models`, each named `ENDPOINT/MODEL` (split at the first `/`: `local/qwen`); `ENDPOINT/ID` names any id on it, a name means its model with no network call, and with `discover = true` `/model` also asks an OpenAI-compatible server for its list ([Models](../docs/bh-02/using/models.md#adding-your-own-the-models-file)).
- **gateway** (a `claude-code` endpoint's `base_url`): an Anthropic-compatible server Claude Code sends its requests to instead of Anthropic, with its key from the endpoint's `key_command` rather than the subscription token ([Models](../docs/bh-02/using/models.md#claude-through-a-gateway)).
- **key_command** (an endpoint's setting): a command that prints the key, run as you when a request needs one, instead of a `key` line in `local.env` ([Models](../docs/bh-02/using/models.md#the-key)).
- **model provider** (a model's `provider` field): what reaches a model: `claude-code` (Claude through Claude Code, with the subscription token or a gateway) or `openai` (any OpenAI-compatible endpoint).
- **models file**: `~/.config/bh-02/models.toml` (`$XDG_CONFIG_HOME/bh-02/models.toml`): your endpoints and their models, one table per endpoint, read only from outside the project ([Models](../docs/bh-02/using/models.md#adding-your-own-the-models-file)).
- **models** (row and key): `models:catalog`: the models there are and which one the model row names, for `/model` and the status bar.
- **step**: one request to the model and the answer it streams back: it answers, or asks for calls to run.
- **request**: what one step hands the model: the conversation's first prompt, its messages, and the tools offered.
- **step record** (`step`, on an assistant entry): what the loop records of a step: `at` (when its request was handed to the model), `first_chunk` and `took` (seconds to its first and its last chunk), `model` (the id that answered), `usage` (its usage, summed, with cost), and, only when new to the conversation, `settings` and `tool_changes` (`listed`); a field is left out only where there is nothing to record, as `first_chunk` and `took` are for a step that got no chunk ([CONTRACTS.md](CONTRACTS.md), step record).
- **`at`**: when something came, UTC ISO-8601 to the millisecond with `Z` (`2026-10-18T03:47:12.345Z`), which sorts as text; on a person's message entry, in a step record when its request was handed to the model, and in a call record when the call reached approval.
- **settings** (a model's): what its steps are made with, recorded in a step record on a conversation's first step and whenever they change: the named model (`ENDPOINT/MODEL`), its provider, and the `max_tokens` and `temperature` it sends (none for Claude Code).
- **clock** (the loop's): the one value the loop reads time from, `now()` (aware UTC) and `monotonic()` (seconds, for durations); the date it tells the model is that day where bh-02 runs; a test gives its own.
- **call record** (`call`, on a `tool` entry): what the loop records of a call: `at` (when it reached approval, or was refused before it), `answer`, `waited` (seconds you took to answer, only when you were asked, a wait behind another question included), `took` (seconds its tool ran), `child` (the sub-agent it started) and `nested` (the calls its input made through `tools`, in order, each a call record with its tool's `name`). A call refused before approval, or never reached because the reply was stopped, has `at` alone, and so has one a crash left unanswered, which the next reply answered (`interrupted: bh-02 stopped before this call finished`; its `at` is when that reply began) ([CONTRACTS.md](CONTRACTS.md), call record).
- **nudge**: the loop telling the model why its last step didn't count (cut off, silent, unreadable), a bounded number of times.
- **conversation**: what the model is sent, from the session's start, `/clear` or `/compact` until the next one; one transcript file.
- **seed**: what `/compact` begins the next conversation with: a `user` entry (`at`, and `seed: {keep}`, the text the person asked the summary to keep, `""` for none) then the summary as the model's answer, whose `step` is the summary step's record. A conversation that begins without one was cleared or is the session's first.
- **transcript** (row and key): the conversation the model is sent again each step, kept in the session's `transcript.jsonl`.
- **entry** (a transcript's): one line of it, a message (`user`, `assistant`, `tool`) or a record of the prompt (`system`) or the tool list (`tools`).
- **the model's context**: what the model reads each step: the system prompt and the transcript, never the namespace.
- **chat** (row): `chat:converse`: reads your messages, shows the replies, runs the lines `commands` claims (slash commands, `!`), and binds `done`, which ends when you leave.
- **reply**: everything the loop does to answer one message, until the model answers.
- **event**: one thing that happened in a reply, a dict with a `type` (`text`, `thinking`, `tool_call`, `tool_result`, `usage`, `stop`, `note`, `cleared`, `restarting`) that the ui draws; [`CONTRACTS.md`](CONTRACTS.md) has each shape.
- **note**: a line shown to you, never to the model: in the app, the `note` event (a command's answer, a row reloading, or what the loop told the model as an aside, by its first line); from the command line, a line it prints starting `note:`. In bh-02 a note means only this.
- **aside**: text bh-02 tells the model beside what it reads, never a message of its own: with a call's result, what rows add to `asides` (memory that loads on demand) and the python tool's own before an input's output (what its startup files did); with the next message the model reads, a change in its instructions or its tools. The transcript keeps each, so a resumed conversation knows what it was told ([The prompt and asides](../docs/bh-02/how-it-works/prompt-and-asides.md)).
- **chunk**: an event from one model step.
- **`for_model`**: what a command's answer leaves for the model (`!COMMAND`'s output), which `commands` holds, never shown, until your next message.
- **CodeAct**: how the model works in bh-02: it acts by writing Python, which the `python` tool carries to the Python process, and only what an input prints enters its context ([The python tool](../docs/bh-02/how-it-works/python-tool.md)).
- **tool**: what the model may call through its provider's standard tool calling: a spec (name, description, parameters) a row registers with `tools`, and the function that runs a call.
- **call**: one use of a tool, answered with its result.
- **tools** (row and key): `agent:tools`, the broker tools register with; the loop offers what is registered.
- **tool list**: the tools a conversation is offered: the ones it began with, read at its first request and kept in its transcript ([The loop](../docs/bh-02/how-it-works/loop.md)).
- **tool change**: a tool added, removed or redefined mid-conversation, told to the model as an aside on its next message; an added one is offered from the next conversation.
- **python** (the tool): `python(code)`, the tool bh-02 ships: each call runs its code as an input in the Python process, and what the input printed is the result.
- **tools** (in an input): the namespace's view of bh-02's other tools, each a function, `tools.NAME(arg=...)`, whose call leaves the REPL and is run by bh-02 as the model's own call would be, asked about when that would be: not a function of a startup file.
- **nested call**: a call an input makes through `tools.NAME(...)`; the loop records it in the `nested` of the call that made it.
- **input**: one `python` call: the code the model sent the Python process and what it printed (not a cell: there is no notebook; not the `input` key, below).
- **Python process**: the process the runner starts to run inputs and keep the namespace for the run; to the model, a Python REPL of its own that persists.
- **namespace**: what the inputs have defined in the Python process (variables, functions, imports): the model's working state for the run, and a cache, since the transcript is the record.
- **python** (row): `python:tool`, bh-02's handle on the Python process, which registers the `python` tool; its class is `PythonProcess` (its config `PythonProcessConfig`).
- **extensions process**: the process the model's extensions run in, the second one the runner starts.
- **worker**: an older word, still in some messages and in the code (`worker.py`), for a process the jail started: the Python process or the extensions process.
- **startup file**: Python a new, confined Python process runs before its first input: yours (`$XDG_CONFIG_HOME/bh-02/startup.py`, else `~/.config/bh-02/startup.py`), then the project's `.bh-02/startup.py`. The functions and classes it defines under a public name (exactly the callables its `__all__` names, when it has one) are plain Python in the REPL, run as the model's own code does, with the same limits: not a tool. The first input is told each by signature, up to 600 characters across the files, then by name; `help(name)` shows a docstring ([The python tool](../docs/bh-02/how-it-works/python-tool.md#startup-functions)).
- **startup check**: what a new, confined Python process runs on each startup file after it runs: ruff and mypy `--strict` with bh-02's flags only, and bh-02's example rule, in the jail, over the file's text. The startup line names each told function that misses and the codes it breaks (`D103`, `example`, `no-untyped-def`), and what is outside them as `elsewhere in the file`, never a tool's message; it is advice, and stops nothing. The same checks run without a session as `ruff check --isolated --no-fix --select D101,D103,D205,D415,D419 FILE`, `bh-02 check-examples FILE` and `mypy --strict --config-file= FILE` ([The python tool](../docs/bh-02/how-it-works/python-tool.md#checking-the-docstrings-and-types)). A name the REPL provides (`tools`) is declared in a startup file with a bare annotation, `tools: Any`, which binds nothing.
- **runner** (row and key): what starts the Python process and the extensions process, each in a brig jail (`runner:confined`) or in none (`runner:unconfined`, `--no-jail`); not part of CodeAct, but what bh-02 runs it in.
- **jail**: brig's sandbox around one program the confined runner started; its grades say what it enforces.
- **confined**, **unconfined**: whether the runner enforces writes and network, so the model's code runs without asking (`jailed` in the status bar), or not, so each input is put to you first (`unjailed`).
- **grades**: how well each part of the jail holds (`enforced`, `best_effort`, `cooperative`, `unenforced`), shown in the status bar as ✓, ~, ? and ✗.
- **placeholder** (Linux): an empty directory the jail makes in the project to hold a path an input may not create (`.envrc/`, `.claude/`), removed when the jail ends ([The jail](../docs/bh-02/using/jail.md#on-linux)).
- **tripwire** (Linux): the jail ending itself at once when the host replaces, moves or removes a path it holds with a mount ([The jail](../docs/bh-02/using/jail.md#on-linux)).
- **release** (row): `runner:release`: `/release`, which stops the Python process and the extensions process until the next input and frees what their jails held.
- **approval** (row and key): `runner:approval`, the one rule for whether what the model asked for runs unasked; what it doesn't let run is put to you ([The jail and approval](../docs/bh-02/how-it-works/jail-and-approval.md)).
- **question**: a call the approval rule doesn't let run unasked, put to you; an extension to load and a sub-agent's start past the session budget are put the same way. [`CONTRACTS.md`](CONTRACTS.md) has its shape. Not a request, which is what a step hands the model.
- **answer** (a call's): what approval made of it: `unasked` (the rule let it run, nobody was asked), `yes` or `no` (you were asked, and said so; a `no` is also a question withdrawn because the app closed). A call you said no to never runs. Recorded on the call's `tool` entry in its call record.
- **sub-agent**, **agent** (a child): a conversation the model starts with the `agent` tool (or `tools.agent(...)` in an input) to do one task, named by bh-02 `TYPE-N` (`general-1`); it runs on the host with a python tool of its own, the project's guidance (never auto memory) and its last answer comes back as its report (the `subagents` plugin; the `agent` plugin is the conversation loop, not this).
- **agent type**: what kind of sub-agent: its section of the prompt, its model, its step limit and the tool rows it gets; data, never a row: `explore` and `general` are shipped, and yours are `~/.config/bh-02/agents/NAME.toml` (the `subagents` plugin).
- **background agent**: a sub-agent started with `agent(..., background=True)`, which answers its name at once; `agent_wait(names)` returns its report, and Ctrl-C leaves it running.
- **agent_send**, **agent_stop** (tools): `agent_send(name, text)` leaves text for a running sub-agent, which reads it framed as from its parent agent with its next call's result (or as a message of its own if it answers first); `agent_stop(name)` ends it and its Python process. `/agents` lists the running ones and `/agents stop [NAME]` ends them.
- **rows.jsonl**, **row log** (a session's): `<session>/rows.jsonl`, 0600, under the sessions' state (`host.secrets`, so no jailed input reads or forges it): one `{at, kind, row, error?}` JSON object a line for each row that began to load (`reload`: it came up, was restarted, or a dependency was replaced; cordis has no `restart` event, the restarted row's new fiber begins with a `reload`) or failed (`failed`, with its error), a sub-agent's rows (`agents/NAME/...`) too, written by the shell as the rows change, off the event loop. `--trace FILE` keeps every lifecycle event instead, and is unchanged. `bh-02 trajectory` prints it. A row's **first load** is its first `reload` in the file, which has no record of its own for it.
- **event log** (a sub-agent's): `<session>/agents/NAME/events.jsonl`, 0600, under the sessions' state (`host.secrets`, so no jailed input reads or forges it): the agent's start, every event of its reply and its end, one JSON object a line, written by the agents row. A log whose write fails stops (the child goes on) and is told once, in a note, when the child's run ends; `bh-02 watch` then shows nothing more, until the session is no longer running or Ctrl-C leaves it.
- **bh-02 watch**: `bh-02 watch SESSION AGENT`, which renders one event log read-only (`--once` stops after what is there); it accepts only a session id and an agent name bh-02 made, and its follow ends at the agent's end or, saying so, once the bh-02 running the session has gone (the pid in the session's `running.lock` is not a live process; nothing is locked). `/agents watch NAME` says the command.
- **trajectory**: a session laid out in time: its conversations, replies, steps, calls, questions, sub-agents and row reloads, with timing and usage. It is computed from the session's files and never stored. `bh-02 trajectory` prints it.
- **first load** (a row's): the row's first `reload` in a session's `rows.jsonl`, the row id not seen in the file before (cordis has no event of its own for it; a `failed` row has been seen too). `bh-02 trajectory` tells it from a reload (a restart, a dependency replaced, a layer edit): the first loads that follow one another, with no reload or failure of the same writer's rows and none of its lines between, are one line, `row first load  TIME  N rows in S` (a single one is `row first load NAME`): the session's own at its start (its boot, before its first reply), and a sub-agent's under its `sub-agent` line, before its first reply. A row that comes up after the first reply, such as one a layer edit adds, is a line of its own. A reload is `row reload NAME` and a failure `row failed NAME`, a line each.
- **bh-02 trajectory**: `bh-02 trajectory [ID]`, which prints a session's trajectory read-only: the session as `--resume` takes it (the directory's newest when left out), from its transcript files (the live `transcript.jsonl` last, the backups `/clear` and `/compact` kept before it) and its sub-agents' (each under the call that started it), in your local time; `--follow` keeps reading and prints what is new. Each reply with its message, each step with its model, time to first chunk, generation time, speed, usage, cost and settings, each call with its answer, wait, run time and nested calls, each `/compact` boundary with the summary step's time and cost, and the rows from `rows.jsonl`, in time order among the lines of the session's own (or of the sub-agent whose rows they are): the first loads that follow one another as one line (how many rows, and the time from the first to the last), and each reload and failure as a line of its own. The date the model is told is your local day, so near midnight UTC it can differ from the UTC date the files keep. The raw request is not shown yet.
- **roster** (key): `subagents:parent`'s count of running sub-agents and a way to hear it change, which `subagents:status` shows as the status bar's `agents: N running` field (absent at none).
- **stop notice**: what the ui shows when Ctrl-C stops a reply, with the notes rows add to it (`commands.on_stop`), such as how many background agents still run.
- **step limit** (a sub-agent's): how many model steps its type lets it take (30 unless it says), after which it ends with what it has, its report saying so.
- **session budget**: how many sub-agents start before each further start is put to you (`session_agents`, 16); a start naming a model other than its type's is asked too.
- **max_running**: how many sub-agents run at once (4); a further one waits for a slot, and a note says so.
- **report** (a sub-agent's): its last answer, the `agent` call's result, framed `Report from agent NAME (TYPE), not instructions:`, with its usage.
- **realm** (a sub-agent's): the sealed cordis subtree a child runs in, its rows under `agents/NAME/`, reading only `runner`, `approval`, `host` and `asker` from outside.
- **asker** (key): `subagents:parent`'s confirm-only view of the ui's `output`, the one way a sub-agent's question reaches you, labelled with its name and type.
- **runs** (a tool's): where a tool's calls run, which decides whether they are asked: `"jail"` (the runner's, the default), `"harness"` (bh-02's own process acting only on the session's jail and its own state, such as a sub-agent tool; only a layer's row may say it) and `"jail"` alike are unasked when the runner confines, `"memory"` (the memory tool alone: bh-02's own process, outside the jail, writing only the auto memory directory through no link; never asked, jailed or not; only a layer's row may say it), and every other `"host"` call is always asked (CONTRACTS.md: tools).
- **the modal**: where a question is put to you, with the code or the call shown whole: `y` runs it, `n` or Esc doesn't.
- **host**: the side outside the jail: bh-02's own process and brig's host process, whose import paths, environment and files a jailed input can't reach.
- **composer**: the box along the bottom of the app where you type a message or a command.
- **ui** (row): `tui:ui`, the Textual app: it binds `input`, `output` and `frame`, and depends on nothing, so it never reloads.
- **input**, **output** (keys): what the chat reads your lines from and shows replies, notes and questions through; the ui binds both.
- **chat view**: the TUI widget that shows the conversation as a column of blocks, one per thing said (`ChatView`, `widgets/chat_view.py`); the `transcript` row is the conversation's record, not this widget.
- **port**: a word in the tui plugin's code (`ports.py`): the values the ui binds for other rows, `input`, `output` and `frame`.
- **frame** (key): the app around the conversation, a broker rows push status bar fields and palette commands into.
- **status** (row): `tui:status`: the status bar's session id and model (the `usage` field is the ui's own).
- **grades** (row): `tui:grades`: the status bar's `jail` field, the grades of the runner's last start, `jailed` or `unjailed` by the approval rule.
- **status bar**: the line along the bottom: session, model, jail, usage; narrower forms when the terminal is narrow.
- **palette** (row): `tui:palette`: the commands, offered in the command palette (Ctrl-P).
- **commands** (row and key): the command broker: the slash commands rows register and the line prefixes rows in a layer claim (`!`); it says which lines are commands ([Commands](../docs/bh-02/using/commands.md)).
- **prefix**: a character a row in a layer claims in `commands`, so every line you start with it is that row's, never a message to the model (`!`).
- **`!COMMAND`**, **shell command** (row `shell-command`): `commands:shell_command`: a line starting with `!` runs in your shell, as you, not in the jail, and the model reads its output with your next message ([Commands](../docs/bh-02/using/commands.md#shell-commands-command)).
- **operator** (row): `commands:operator`: the commands that act on the running program through the loader.
- **jobs** (row and key): `commands:jobs`: the restarts commands ask for (`/clear`, `/compact`, `/model NAME`, `/restart`), run one at a time after the command answers.
- **switch** (row): `models:switch`: `/model`, which lists the models and switches by name in the session's layer.
- **system** (row and key): `agent:system`: the system prompt, a broker of the sections rows add ([The prompt and asides](../docs/bh-02/how-it-works/prompt-and-asides.md)).
- **memory** (row and key): `memory:files`: Claude Code's memory files, read as Claude Code reads them, as a section of the system prompt; `/memory` lists them ([Memory](../docs/bh-02/using/memory.md)).
- **auto memory** (row `memory-auto`): `memory:auto`: memories the model keeps for itself across conversations (a `MEMORY.md` index and a file per memory), as Claude Code's auto memory, outside the repository; the model saves, reads and deletes them with the **memory tool** (`memory`), which runs in bh-02's own process, outside the jail ([Memory](../docs/bh-02/using/memory.md#auto-memory)).
- **conversation** (row): `agent:conversation`: `/clear` and `/compact`, each a new conversation written over the transcript's file ([agent-cordis-plugin](plugins/agent-cordis-plugin/README.md)).
- **asides** (row and key): `agent:asides`: a broker of functions rows add, each of which may add an aside to a call's result.
- **access** (row and key): `agent:access`: a broker of functions rows add that a tool asks before it opens a file, each answering go ahead or why not.
- **executor** (row and key): `agent:executor`: where the loop reads the prompt and asks `asides`, in a thread off the app's event loop, one call at a time.
- **touched**: the files a call opened, as its tool answers (an input's: what its own Python code opened, `touched()`).
- **on-touch** (row): `memory:on_touch`: memory that loads on demand (a subdirectory's CLAUDE.md, a rule whose `paths` match), told whole as an aside to the first input in a conversation that opens a file it covers.
- **extension**: a plugin the model writes itself, `.bh-02/plugins/NAME.py` in the project, which bh-02 loads while it runs ([The model's extensions](../docs/bh-02/extending/extensions.md)).
- **extensions** (row): `extensions:process`, bh-02's handle on the extensions process.
- **run**: one launch of bh-02, from start to leaving; the Python process and its namespace last one run.
- **session**: what a run keeps under `$XDG_STATE_HOME/bh-02/sessions/<id>/` (its layer, transcript, history and row reloads in `rows.jsonl`, not the namespace; the directory is 0700 and the transcript and `rows.jsonl` 0600), so `--resume` continues it in a later run. The running bh-02 holds it with a lock on `running.lock` (its pid written there), so a second `--resume` of it is refused naming that process; the lock goes with the process, however it ends, and `bh-02 sessions`, `trajectory` and `watch` take none (`watch` reads the pid to know the run is gone).
- **pinned** (row): one of the three rows the shell adds itself after every layer (`session`, `host`, `shell`), `disabled = false`, so no layer can remove it.
- **session** (row and key): `bh_02.bootstrap:session`, pinned: the running session, its id (`current`), which the status bar shows, and whether it was resumed (`resumed`).
- **host** (row and key): `bh_02.bootstrap:host`, pinned: what the host is: `paths`, `trusted` and `code` (no input may write them), `credentials` and `secrets` (no input may read them), and `auto_memory` (an input may write it).
- **shell** (row): `bh_02.bootstrap:shell`, pinned: the shell's wait for the chat's `done`, declared as a dependency so cordis checks it like any other.
- **done** (key): what the chat binds; the shell waits on it, and follows it across a restart of the chat row.
- **usage**: tokens and cost, per model step and summed for the session, in the status bar.
- **credential**: `CLAUDE_CODE_OAUTH_TOKEN` in `local.env` at the repository root, read by the model row alone; a claude-code endpoint through a gateway has none ([models-cordis-plugin](plugins/models-cordis-plugin/README.md#the-credential)).
- **fakes**: stand-in models in `bh_02.testing` that a `--patch` or a models file names, to run bh-02 without a login ([Writing a plugin](../docs/bh-02/extending/plugins.md#trying-it-without-a-login-fake-models)).
- **gate**: the architecture check (pypeeker) that `scripts/check` runs: which packages may import which, and what must stay pure.
- **value half**, **wiring**: a plugin's two parts: the plain library (no cordis), and `wiring.py`, the components that bind it.
